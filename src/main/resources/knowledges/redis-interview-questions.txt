# Redis 面试题库

## 数据结构

【考点】Redis 有哪些基本数据类型？各自适用场景？
【参考答案】五种基础类型：String（缓存、计数器、分布式锁）、Hash（对象属性存储）、List（消息队列、最新列表）、Set（去重、共同好友）、ZSet（排行榜、延迟队列）。三种高级类型：Bitmap（签到统计）、HyperLogLog（UV 基数统计）、GEO（地理位置附近的人）。底层实现有动态字符串 SDS、跳表 skiplist、压缩列表 listpack、哈希表 dict 等。

【考点】Redis 为什么快？
【参考答案】① 纯内存操作，读写速度纳秒级；② 单线程模型避免线程切换和锁竞争（6.0 后网络 IO 多线程，命令执行仍单线程）；③ IO 多路复用（epoll）支持高并发连接；④ 高效的数据结构（SDS、跳表、渐进式 rehash）。但单线程也意味着要避免慢查询（如 keys *、大 key 删除）。

## 持久化

【考点】RDB 和 AOF 的区别？如何选择？
【参考答案】RDB 是定时快照，文件紧凑、恢复快，但可能丢失最后一次快照后的数据，fork 子进程时会短暂阻塞主线程；AOF 是追加写日志，默认每秒 fsync，最多丢 1 秒数据，文件更大、恢复更慢，但可读可修复。生产环境通常两者都开：RDB 用于灾难恢复，AOF 用于数据安全，混合持久化（AOF 中包含 RDB 快照）兼顾两者优点。

【考点】AOF 重写机制是什么？
【参考答案】AOF 文件随写命令增长会越来越大，重写时 fork 子进程根据当前内存数据生成最小命令集写入新文件，期间新命令写入重写缓冲区，完成后追加并原子替换旧文件，从而压缩文件体积。重写不阻塞主线程（copy-on-write 机制）。

## 缓存三大问题

【考点】缓存穿透、缓存击穿、缓存雪崩分别是什么？如何解决？
【参考答案】穿透：查询不存在的数据，缓存和数据库都没有，请求全打到数据库——用布隆过滤器拦截或缓存空值（短过期时间）。击穿：热点 key 过期瞬间大量并发请求打到数据库——互斥锁（只有一个线程回源重建）或逻辑过期（不等重建，先返回旧值异步更新）。雪崩：大量 key 同时过期或 Redis 宕机导致数据库压力骤增——过期时间加随机值、多级缓存、限流降级、Redis 高可用（主从 + 哨兵/集群）。

【考点】如何保证缓存与数据库的一致性？
【参考答案】先更新数据库再删除缓存（Cache Aside 旁路缓存）：写操作更新 DB 后删除缓存，读操作未命中时回源并回填。删除失败可用消息队列重试或订阅 binlog（如 Canal）异步补偿。延迟双删解决删除前有旧值写入的并发窗口。强一致场景需要分布式锁或读写串行化，多数业务场景最终一致即可。

## 分布式锁

【考点】如何用 Redis 实现分布式锁？有哪些注意点？
【参考答案】核心命令：SET key value NX EX 秒数（加锁原子操作），value 用唯一标识（如 UUID+线程 id），释放时用 Lua 脚本先判断 value 再 DEL，防止误删他人锁。注意点：锁要设过期时间防止死锁；过期时间要大于业务执行时间，业务长时用看门狗自动续期（Redisson 的 watchdog）；主从切换可能导致锁丢失，强一致场景用 RedLock 或换 Zookeeper/etcd 实现。
