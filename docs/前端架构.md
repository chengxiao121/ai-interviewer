# 前端架构文档

> 目的：让每次开启新对话的 AI（或新接手的开发者）读完这一篇，就能快速了解前端的选型、目录、数据流与扩展方式。
> 前端覆盖后端全部交互能力（阶段 2.2 及之前的接口），并为后续阶段（评估报告、多 Agent 路由）预留扩展点。

---

## 1. 定位与技术选型

前端是 AI 智能面试官的用户界面，提供：流式面试对话、会话管理、知识库管理三大功能区。

| 维度 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3（`<script setup>` + Composition API） | 响应式数据天然契合 SSE 流式聊天；生态成熟、文档中文友好 |
| 构建 | Vite | 启动快、HMR 好、配置简单；proxy 解决开发态跨域 |
| 语言 | TypeScript | 类型安全，接口契约清晰，重构可持续扩展 |
| 状态 | Pinia | Vue 官方推荐，API 简洁，store 按域拆分易于扩展 |
| 路由 | Vue Router | 多页面（聊天/会话/知识库）切换 |
| 样式 | 自写轻量 CSS（CSS 变量 + 基础组件类） | 不引重型 UI 库，架构干净，后续可平滑接入组件库 |

> 不选 React/Next：本项目是单页应用 + SSE 流式，Vue3 响应式更直观；不选 SSR，无需 SEO。
> 不引 UI 库：当前页面少、交互明确，自写 CSS 更可控；若后续组件增多再按需引入。

## 2. 工程位置与前后端协同

```
AI-agent-test/
├── src/                 后端（Spring Boot）
├── frontend/            前端（Vite 独立工程，与 src/ 平级）
└── docs/                架构文档
```

### 开发态
- 前端 `npm run dev` → `http://localhost:5173`
- `vite.config.ts` 配置 proxy：`/api` → `http://localhost:8080`，免 CORS
- 后端 `mvn spring-boot:run` → 8080

### 生产态
- 前端 `npm run build` → `frontend/dist/`
- 将 `dist/*` 拷贝到 `src/main/resources/static/`，由 Spring Boot 同源托管
- 访问 `http://localhost:8080/` 即前端，`/api/*` 走后端，无跨域
- 前端路由用 **hash 模式**（`/#/chat`），浏览器不会把前端路径发给服务器，无需服务端 SPA 回退

> 后端 pom 已含 `spring-boot-starter-thymeleaf`，但前端采用静态托管方式，不依赖 Thymeleaf 模板。

## 4. 分层职责说明

### 4.1 api/ 接口封装层
- `request.ts`：统一 `fetch` 封装，base 路径 `/api`，默认 JSON，统一错误抛出。
- `assistant.ts`：
  - `chatSSE(userMessage, sessionId, onChunk)` —— 调用 `utils/sse.ts` 解析 SSE，每收到一片文本回调 `onChunk`，返回可 abort 的控制器
  - `listSessions()` / `getHistory(sessionId)` / `clearSession(sessionId)`
- `knowledge.ts`：`syncKnowledge()` / `listDocuments()`
- 该层只管「怎么调后端」，不持有状态，便于后端契约变更时只改这一处。

### 4.2 utils/sse.ts —— SSE 解析器
- 后端 chat 是 `POST + text/event-stream`，`EventSource` 不支持 POST，故用 `fetch` + `ReadableStream` 手解 SSE 帧
- 按 `\n\n` 分帧、`data:` 前缀取数据、自动解码 UTF-8，逐片回调
- **同帧多条 `data:` 行按 `\n` 拼接**（SSE 规范；Spring 写出器对分片内换行做 `data:` 续行转义，前端拼接后还原换行，否则换行丢失、回答挤成一段）
- 暴露 `AbortController` 支持中断生成

### 4.3 stores/ Pinia 状态层
- `chat.ts`：`messages`（当前会话消息列表）、`sessionId`、`streaming`（是否生成中）、`abort()`；action `send(text)` 推入用户消息后流式追加 assistant 消息
- `sessions.ts`：`sessions` 列表、`loadList()` / `loadHistory(id)` / `clear(id)` / `switchTo(id)`（切换当前会话并载入历史）
- `knowledge.ts`：`documents`、`syncing`、`loadDocs()` / `sync()`
- store 是唯一状态来源，view 只消费和派发 action。

### 4.4 views/ 页面
- **ChatView**：消息流（MessageBubble 列表）+ ChatInput；展示流式打字机；顶部「新建会话」
- **SessionsView**：会话列表 + 操作（查看历史/载入聊天/清空）；点击会话切换到 ChatView 并载入历史
- **KnowledgeView**：同步按钮 + DocTable（文件名/块数/状态/来源/入库时间）

### 4.5 components/ 可复用组件
- `AppSidebar`：导航 + 当前会话快速切换
- `MessageBubble`：按 role 渲染 user/assistant 气泡
- `ChatInput`：textarea 自适应高度 + 发送（Enter 发送 / Shift+Enter 换行）
- `DocTable`：文档元数据表格

## 5. 页面 ↔ 后端接口映射表

| 前端页面/组件 | 后端接口 | 说明 |
|---|---|---|
| ChatView | `POST /api/assistant/chat` | SSE 流式面试对话 |
| SessionsView / AppSidebar | `GET /api/assistant/memory` | 会话列表 |
| SessionsView | `GET /api/assistant/memory/{id}` | 载入历史到聊天 |
| SessionsView | `DELETE /api/assistant/memory/{id}` | 清空会话 |
| KnowledgeView | `POST /api/knowledge/sync` | 手动同步知识库 |
| KnowledgeView | `GET /api/knowledge/documents` | 文档元数据表格 |

> 覆盖后端全部接口，无遗漏。

## 6. 数据流

```
用户操作 (输入/点击)
   │
   ▼
view 调用 store action
   │
   ▼
store action 调用 api/ 层
   │
   ▼
api 层请求后端 (/api/*)
   │
   ▼
后端返回 (SSE 流 / JSON)
   │
   ▼
api 层回调更新 store state
   │
   ▼
Vue 响应式 → 视图自动更新
```

例：发送消息
1. ChatView 调 `chatStore.send(text)`
2. store 推入 user 消息，置 `streaming=true`，调 `assistant.chatSSE(...)`
3. `sse.ts` 逐片回调 → store 追加到 assistant 消息文本
4. 响应式触发 MessageBubble 实时渲染（打字机效果）
5. 流结束 `streaming=false`

## 7. 扩展点说明

后续阶段（2.3 工具调用 / 2.5 MCP / 3 长期记忆 / 4 多 Agent）新增前端能力时，**只加文件不改旧代码**：
- 新接口 → 新增 `api/xxx.ts`
- 新状态 → 新增 `stores/xxx.ts`
- 新页面 → 新增 `views/XxxView.vue` + `router/index.ts` 加一条路由
- 新组件 → 新增 `components/Xxx.vue`

预判扩展：
- 评估报告页：`/report`，展示评估 Agent 输出（得分/薄弱点/建议）
- 多 Agent 路由可视化：`/agents`，展示意图路由分发与各 Agent 状态
- 工具调用面板：聊天页侧边展示当次对话触发的 Tool 调用记录

## 9. 与后端契约的关键约定

1. chat 接口为 **POST + `text/event-stream`**，body `{userMessage, sessionId}`，因面试回答长，避免 URL 长度上限
2. SSE 数据为纯文本分片（后端 `Flux<String>`）；Spring 对分片内 `\n` 自动做 `data:` 续行转义（控制器勿再手动转义），前端按 SSE 规范把同帧多条 `data:` 行用 `\n` 拼接还原换行
3. `sessionId` 默认 `default`，前端新建会话时生成 UUID
4. 历史消息 DTO：`{role: "USER"|"ASSISTANT", content: string}`（后端 `ChatMessageDto`，role 为 `MessageType.name()`）
5. 文档元数据：`{fileName, chunkCount, status, source, ingestedAt}`（ingestedAt 为 ISO 字符串）
