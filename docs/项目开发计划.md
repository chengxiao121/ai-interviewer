# AI 智能面试官项目 —— 简历级实施计划

> 项目定位：基于 Spring AI Alibaba 1.1 从 0 到 1 构建的 AI 智能面试官（多 Agent 面试陪练系统），
> 具备记忆、知识检索（题库 RAG）、工具调用三大核心能力，并支持多 Agent 协作编排。
> 一句话介绍：**「用自己做的 AI 面试官准备面试」**。

## 技术栈

- Spring Boot 3.5.7
- Spring AI 1.1.2
- Spring AI Alibaba 1.1.2.0
- 阿里百炼 OpenAI 兼容协议（qwen3.7-plus / qwen3.7-text-embedding，DashScope 原生协议不可用）
- Redis Stack（短期记忆 + 题库向量检索）
- PostgreSQL 16（业务数据持久化 + 题库文档元数据）
- Spring Data JPA（业务数据访问层）
- MCP（阶段 2.5 自研 MCP Server，暴露题库/评分能力）
- Docker Compose（本地环境一键启动）

## 总体架构

```
用户 ──REST API──> AssistantController (SSE 流式)
                      │
                      ▼
              ┌─ 意图路由 Agent (LlmRoutingAgent) ─┐
              │                                    │
         闲聊 Agent                         面试主流程 Agent
       (纯 LLM 对话)               (出题 → 追问 → 评估 流水线)
              │                                    │
              └───────────────┬────────────────────┘
                              ▼
                      Agent 核心能力层
         ┌──────────────┬──────────────┬──────────────────┐
         ▼              ▼              ▼                  ▼
     短期记忆        长期记忆        工具调用            知识检索
  Redis 滑动窗口   摘要式记忆     @Tool 自定义        RedisStack 向量库
  (会话隔离)     (薄弱点跨会话)  (评分/统计/收藏)   (面试题库+分块+Embedding)
         │              │              │                  │
         └──────────────┴──────────────┴──────────────────┘
                              ▼
                   Redis Stack │ PostgreSQL (业务数据+题库元数据)
                              │
                  MCP Server (自研, @McpTool 暴露题库/评分能力)
```

## 阶段 0：环境搭建（半天）

- 启动 Docker Desktop
- 编写 `docker-compose.yml`：
  - **redis/redis-stack:latest**（必须 Stack 版，含 RediSearch 向量检索模块）
  - **postgres:16**（业务数据 + 题库文档元数据持久化）
- 验收：两个容器健康运行

### docker-compose.yml

```yaml
services:
  # Redis Stack：短期记忆 + 向量检索（必须 Stack 版，普通 Redis 没有向量模块）
  redis-stack:
    image: redis/redis-stack:latest
    container_name: redis-stack
    ports:
      - "6379:6379"    # Redis 服务
      - "8001:8001"    # RedisInsight 可视化界面（浏览器打开 localhost:8001 看向量数据）
    volumes:
      - redis-data:/data
    restart: unless-stopped

  # PostgreSQL：业务数据 + 题库文档元数据（阶段 2.2）
  postgres:
    image: postgres:16
    container_name: aiagent-postgres
    environment:
      POSTGRES_USER: admin        # 初始数据库用户名
      POSTGRES_PASSWORD: admin123 # 该用户的密码（仅本地开发用）
      POSTGRES_DB: aiagent        # 初始化时自动创建的默认数据库名
    ports:
      - "5432:5432"
    volumes:
      - pg-data:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  redis-data:
  pg-data:
```

## 阶段 1：升级 Spring AI 1.1.2 + 接入 Redis 记忆/向量（保留 OpenAI 兼容协议接入）（半天~1天）

### pom.xml 改造要点

- BOM：`spring-ai-bom` 1.1.0 → 1.1.2 + 新增 `spring-ai-alibaba-bom:1.1.2.0`（extensions-bom 用不到，不加）
- **保留** `spring-ai-starter-model-openai`（模型走百炼 OpenAI 兼容端点，不换 dashscope starter）
- 新增：`spring-ai-starter-vector-store-redis`（Redis Stack 向量存储）
- 新增：`spring-ai-alibaba-starter-memory-redis`（短期记忆 Redis 持久化）
  - ⚠️ 必须手写 `<version>1.1.2.0</version>`：`spring-ai-alibaba-bom` 不管理 memory 模块版本
  - ⚠️ 不引入聚合包 `spring-ai-alibaba-starter-memory`（会捆绑 jdbc/tablestore/elasticsearch 实现，太臃肿）
- 新增：`commons-pool2`（向量库自动装配强依赖 Jedis 客户端，Boot 默认 Lettuce 需要切换）
- **不引入** `spring-ai-alibaba-starter-rag`（捆绑 dashscope 生态；RAG 用核心组件自建：TokenTextSplitter + QuestionAnswerAdvisor + RedisVectorStore）
- `spring-ai-alibaba-agent-framework` 推迟到阶段 3、MCP 相关 starter 推迟到阶段 2.5 再引入（少加少出错）

- API Key 按开发阶段保留硬编码
### AgentConfig 改造要点

- `InMemoryChatMemoryRepository` → **手动创建** `JedisRedisChatMemoryRepository` Bean（memory-redis jar 不带自动装配，连接参数复用 `spring.data.redis.*`）
- 删除手写的 `SimpleVectorStore` Bean（Redis 向量库自动装配 `VectorStore`）
- 保留 `MessageChatMemoryAdvisor` + `QuestionAnswerAdvisor`（Builder 写法不变）
- 删除 `OpenAiApi`、`EmbeddingModel`、`SimpleVectorStore` 导入（不再使用）

```java
@Configuration
public class AgentConfig {

    // 短期记忆存储：Redis 持久化（memory-redis starter 不带自动装配，手动创建 Bean）
    // 连接参数复用 spring.data.redis.* 配置，不用再写死
    @Bean
    public ChatMemoryRepository chatMemoryRepository(RedisProperties redisProperties) {
        return JedisRedisChatMemoryRepository.builder()
                .host(redisProperties.getHost())
                .port(redisProperties.getPort())
                .database(redisProperties.getDatabase())
                .build();
    }

    // 短期记忆：滑动窗口（最多保留 20 条消息）+ Redis 持久化
    @Bean
    public ChatMemory chatMemory(ChatMemoryRepository chatMemoryRepository) {
        return MessageWindowChatMemory.builder()
                .chatMemoryRepository(chatMemoryRepository)
                .maxMessages(20)
                .build();
    }

    // 记忆顾问：自动把历史消息注入每次请求（会话由 sessionId 隔离）
    @Bean
    public MessageChatMemoryAdvisor chatMemoryAdvisor(ChatMemory chatMemory) {
        return MessageChatMemoryAdvisor.builder(chatMemory).build();
    }

    // RAG 顾问：VectorStore 由 spring-ai-starter-vector-store-redis 自动装配（Jedis 客户端）
    @Bean
    public QuestionAnswerAdvisor questionAnswerAdvisor(VectorStore vectorStore) {
        return QuestionAnswerAdvisor.builder(vectorStore)
                .searchRequest(SearchRequest.builder()
                        .similarityThreshold(0.7)
                        .topK(3)
                        .build())
                .build();
    }

}
```

> ⚠️ 记忆仓库实现类在 1.1.2.0 已按客户端拆分为 `Jedis/Lettuce/RedissonRedisChatMemoryRepository`（不再有统一的 `RedisChatMemoryRepository`），本项目用 Jedis 版，与向量库客户端保持一致。

### 验收标准

- `/api/assistant/chat` 端点正常流式返回
- 同一 sessionId 内多轮对话有记忆
- Redis 里能看到记忆和向量相关的 key

## 阶段 2：单 Agent 完整闭环（3~4天）⭐ 核心阶段

### 2.1 短期记忆

- `JedisRedisChatMemoryRepository` 持久化 + `MessageWindowChatMemory` 滑动窗口
- 会话隔离：`sessionId` → `ChatMemory.CONVERSATION_ID`
- 新增会话管理 API：查历史、清空会话
- 面试场景落点：会话内多轮追问不重复、不丢上下文（「我刚才答的第三题是什么」）

### 2.2 RAG 完整链路

**题库文档存储：外部目录为主，classpath 兜底**

- 知识库内容 = 面试题库 / 八股 / 岗位 JD 文档（运营方维护，非用户上传）
- 配置项 `app.knowledge.path=file:./data/knowledges/`，默认指向项目根目录下 `data/knowledges/`
- 启动时加载逻辑：
  1. 外部目录不存在 → 自动创建，日志提示"已创建目录，把文档放这里"
  2. 目录存在且有文件 → 使用外部文档（真实题库优先）
  3. 目录为空 → 回退 `classpath:knowledges/*.txt`（示例题库，保证开箱即用）
  4. 日志明确打印当前数据源，避免误判
- 好处：改题库不用重新打包/重启；`ResourcePatternResolver` 原生支持 file:/classpath: 双协议，将来换对象存储只改一个配置

**题库文档元数据入 PostgreSQL**：新建 `KnowledgeDocument` 表（文件名、块数量、入库时间、状态、内容哈希）

- 幂等入库：启动时对比目录与元数据表，哈希/块数未变化的文档跳过，新增/变更才重新入库
- 增量删除：目录中已删的文档 → 按 docId 前缀清理 Redis 中对应块

- `KnowledgeBaseService`：扫描目录 → `TokenTextSplitter` 分块 → `vectorStore.add()` 入库（块级元数据 docId/chunkIndex 随向量写入 Redis）
- 用 `ApplicationRunner` 启动时自动入库 + 手动入库 API
- ⚠️ 维度对齐：RedisVectorStore 1.1.2 建索引时按 `EmbeddingModel.dimensions()` 实时取值（实测 qwen3.7-text-embedding 默认 1024 维，与已建索引 `ai-agent-index` dim=1024 一致，无需手动改索引；启动时打印维度日志留证）
- 验收：对话「考我一道 Java 并发题」能引用题库文档回答；PG 表有入库记录；目录增删文档后重启/调 API 能增量同步

### 2.3 Function Calling 自定义工具 ⭐ 简历重点

| 工具 | 说明 | 技术亮点 |
|------|------|---------|
| `calculator` | 分数/时长计算 | 纯函数工具 |
| `currentDateTime` | 当前时间 | 展示多参数工具 |
| `scoreRecord` | 保存单题评分 | **PostgreSQL 持久化**，展示 Function Calling 落库 |
| `questionStats` | 答题统计（答对率/薄弱考点） | 聚合查询 + 落库 |
| `favoriteQuestion` | 题目收藏 | 展示 CRUD 工具 |
| `interviewRecord` | 面试记录增删查 | 完整 CRUD 链路 |

- 用 `@Tool` + `@ToolParam` 注解，注册到 ChatClient 的 `defaultTools()`
- 新建 `InterviewRecord` / `ScoreRecord` 等实体 + JPA 仓储
- 验收：对话「考我一道 Java 并发题」「我答得怎么样，记下来」「我有哪些薄弱考点」链路全通

### 2.4 可观测性

- `SimpleLoggerAdvisor` 打印请求/响应日志
- 工具调用日志（记录每次 Tool 调用的名称、入参、耗时）

## 阶段 3：Agent 升级（2天）⭐ 简历亮点

### 3.1 ReActAgent 显式推理循环

- 用 `spring-ai-alibaba-agent-framework` 的 `ReactAgent` 替代裸 ChatClient
- 展示「思考 → 行动 → 观察」链路，`MemorySaver` 保存 Agent 状态

### 3.2 自研摘要式长期记忆 ⭐ 最大亮点

- 当对话历史超过滑动窗口（如 20 条）时，触发 LLM 摘要压缩
- 摘要向量化存入 Redis，下次新会话通过语义检索"回忆"历史
- 面试场景落点：**跨会话记住求职者薄弱点**（评估 Agent 写入 → 下次面试出题 Agent 重点考察「上次你 Redis 持久化答得不好」）
- 简历话术：**"设计双层记忆架构，解决大模型上下文窗口限制与跨会话遗忘问题"**

### 3.3 流式输出优化

- 保持 SSE 流式（打字机效果），出题/追问/评估各阶段输出中间状态提示（如「正在评估你的回答…」）

### 验收标准

- 与面试官 Agent 聊 30+ 轮，第 31 轮仍能记得第 1 轮的关键信息（跨窗口）
- 开新会话也能回忆旧会话的薄弱考点

## 关键风险提示

1. **Redis 必须用 Stack 版**（普通 Redis 无向量检索模块）
2. `initialize-schema: true` 首次启动自动建向量索引，之后可关
3. API Key 开发期硬编码，公开仓库前移到环境变量并去百炼控制台重置（旧 key 已在 git 历史里）
4. **向量维度已实测对齐**：qwen3.7-text-embedding 默认 1024 维，与已建索引一致；若换模型/改 dimensions 参数，需先检查索引维度
5. **Windows 中文系统 JVM 默认 GBK**，会导致 Redis 记忆中文乱码（存成 `?`）：项目根目录 `.mvn/jvm.config` 已加 `-Dfile.encoding=UTF-8`；IDEA 直接运行时 Run Configuration 的 VM options 也要加
6. **本机若装有原生 Redis 会抢占 6379**：普通 Redis 无向量模块，应用连上后会报 `unknown command 'FT._LIST'`，需停掉原生 Redis（`net stop Redis`）
7. **Spring AI 1.1.2 Redis 向量库自动装配强依赖 Jedis 客户端**：必须 `spring.data.redis.client-type=jedis` + `commons-pool2`，否则 VectorStore Bean 创建失败
8. 每个阶段结束都 git commit，方便简历上展示 commit 历史
9. **PostgreSQL 连接信息以根目录 docker-compose.yml 为准**（admin/admin123，库 aiagent），与本文档早期版本不同
10. 外部知识目录 `data/knowledges/` 默认 gitignore（示例题库放 `resources/knowledges` 兜底），避免内部资料被提交进公开仓库
